Python cho AI

Python ở cấp độ sản xuất — typing, async, pydantic, FastAPI — cùng sự thành thạo thực sự với hệ sinh thái AI của Python. Được xây dựng riêng cho lập trình viên fullstack JS/TS: chuyển đổi những gì bạn đã biết, bỏ đi những gì không áp dụng được, và đạt chất lượng sẵn sàng phát hành trong hai tuần.

Vì sao nó quan trọng với một FDE: Toàn bộ hệ sinh thái AI (SDK, framework, công cụ đánh giá, fine-tuning) đều ưu tiên Python. Một lập trình viên fullstack JS/TS có thể xoay sở (Vercel AI SDK), nhưng thiếu Python là một trần cứng.

Cách một lập trình viên JS nên học phần này: chuyển đổi, không phải học từ đầu

Bạn không phải người mới bắt đầu. Bạn đã sở hữu những khái niệm khó: closures, promise/future, event loop, module, HTTP, JSON, kỷ luật kiểm thử, hệ thống kiểu. Học Python với tư cách một lập trình viên JS kỳ cựu là ~80% đổi tên và ~20% các mô hình tinh thần thực sự mới. Con đường hiệu quả là tấn công thẳng vào 20% — đó là Phần II và V của module này — và để 80% đến một cách tự nhiên qua các bài thực hành. Cụ thể, danh sách những thứ thực sự mới rất ngắn: event loop theo lựa chọn (opt-in), khoảng trắng có ý nghĩa, mô hình biến đổi (mutability) (và cái bẫy tham số mặc định của nó), type hint tồn tại ở thời điểm chạy (đó là lý do pydantic có thể tồn tại), và GIL. Mọi thứ còn lại là một bảng ánh xạ, bạn sẽ tìm thấy bên dưới.

Khuôn mẫu hai tuần hiệu quả: ngày 1–2 → Phần II + Bài thực hành 1 (môi trường + chuyển một tiện ích); ngày 3–6 → Phần III + Bài thực hành 2 (typing, pydantic, các cuộc gọi Claude đầu tiên); ngày 7–9 → Phần V + Bài thực hành 3 (async); ngày 10–14 → Phần IV + Bài thực hành 4 (dịch vụ bằng chứng FastAPI). Viết Python mỗi ngày; khả năng đọc Python trôi chảy đến miễn phí, viết Python theo phong cách chuẩn chỉ đến qua luyện tập.

Năm khác biệt thực sự (nơi trực giác JS phản bội bạn)

1 · Event loop là tùy chọn (opt-in). Đây là sự đảo ngược khái niệm lớn nhất. Trong Node, mọi thứ chạy trên event loop dù bạn có yêu cầu hay không; await là sẵn có. Trong Python, thế giới mặc định hoàn toàn đồng bộ (synchronous) — một script đơn giản không hề có event loop. Async tồn tại, và nó rất xuất sắc (Phần V), nhưng bạn phải khởi động nó một cách tường minh bằng asyncio.run(main()), đánh dấu hàm bằng async def, và sử dụng các thư viện hỗ trợ async xuyên suốt. Thất bại kinh điển: gọi một hàm chặn (như thư viện requests đồng bộ, hoặc time.sleep) bên trong một hàm async — không có gì báo lỗi, nhưng toàn bộ event loop bị đóng băng trong lúc chờ. Node làm cho việc mắc lỗi này trở nên khó; Python tin tưởng bạn sẽ không mắc.

JavaScript — async là sẵn có 
// every function can await; the loop is
// always running underneath
const r = await fetch(url);
const data = await r.json();
Python — async là một lựa chọn 
import asyncio, httpx

async def main():
    async with httpx.AsyncClient() as c:
        r = await c.get(url)
        data = r.json()

asyncio.run(main())  # YOU start the loop

2 · Độ thật (truthiness) rộng hơn — và ngược lại đối với container. Trong JS, [] và {} là truthy (một sự thật đã gây ra hàng nghìn lỗi). Trong Python, container rỗng là falsy: [], {}, "", set(), cùng với 0 và None. Python theo phong cách chuẩn dựa vào điều này: if not results: nghĩa là "nếu danh sách rỗng". Cái bẫy cũng chạy theo chiều ngược lại — if response.count: là False khi count bằng 0, điều đó có thể không phải ý bạn. Khi "0 là một giá trị hợp lệ" là điều quan trọng, hãy viết if count is not None: một cách tường minh.

3 · Tham số mặc định có thể biến đổi (mutable) — cái bẫy tự bắn vào chân nổi tiếng. Giá trị mặc định được đánh giá một lần, tại thời điểm định nghĩa hàm, không phải mỗi lần gọi. Do đó một giá trị mặc định mutable được chia sẻ qua mọi lần gọi: 

def add_message(msg: str, history: list[str] = []):  # BUG: one shared list
    history.append(msg)
    return history

add_message("hello")   # ['hello']
add_message("again")   # ['hello', 'again']  ← leaked from the first call!

# The idiom every Python codebase uses instead:
def add_message(msg: str, history: list[str] | None = None):
    history = history if history is not None else []
    history.append(msg)
    return history

Điều này cắn mã AI liên tục vì mã chat truyền danh sách tin nhắn ở khắp nơi. Ruff gắn cờ nó (B006) — một lý do nữa khiến linting là bắt buộc (Phần IV).

4 · Module và import. Import trong Python đơn giản hơn câu chuyện ESM/CJS nhưng có những quy luật vật lý riêng: một module là một tệp .py, một package là một thư mục chứa __init__.py, và import phân giải dựa trên sys.path — đó là lý do chạy python src/app/main.py trực tiếp thường làm hỏng import tương đối trong khi python -m app.main (hoặc chạy qua uv từ thư mục gốc dự án) lại hoạt động. Không có default export; from anthropic import Anthropic là import có tên; import numpy as np là namespace-and-alias. Hai quy tắc giữ bạn an toàn: luôn chạy từ thư mục gốc của dự án, và không bao giờ đặt tên tệp trùng với tên một thư viện (anthropic.py trong thư mục của bạn sẽ che khuất SDK thật — một lỗi của người mới cực kỳ gây bực bội).

5 · Xử lý lỗi: EAFP thay vì LBYL. Văn hóa JS thường kiểm tra trước khi hành động ("nhìn trước khi nhảy"). Văn hóa Python ưa thích "xin thứ lỗi dễ hơn xin phép" — cứ làm việc đó, rồi bắt ngoại lệ cụ thể. Đây không chỉ là vấn đề phong cách: trong mã đồng thời, kiểm tra-rồi-hành động có một cửa sổ race; try/except thì không. Hai phong cách quan trọng với công việc AI: bắt các ngoại lệ cụ thể (except: trần nuốt KeyboardInterrupt và các lỗi thật), và dùng chuỗi ngoại lệ (exception chaining) để giữ nguyên căn nguyên gốc:

Typing, pydantic, FastAPI: ngăn xếp mà mọi dịch vụ AI sử dụng

Type hint: giống kiểu TS, ngoại trừ chúng tồn tại ở thời điểm chạy

Type hint của Python trông giống một phương ngữ TS và kiểm tra giống như vậy (qua pyright/mypy), với một khác biệt sâu sắc làm nên toàn bộ ngăn xếp AI: kiểu TS bị xóa ở thời điểm biên dịch; hint của Python sống sót vào chương trình đang chạy. Một thư viện có thể đọc total: float từ class của bạn ở thời điểm chạy và hành động dựa trên nó. Chỉ riêng sự thật đó là lý do pydantic có thể xác thực JSON dựa trên annotation của bạn, vì sao FastAPI có thể tạo một spec OpenAPI từ chữ ký hàm, và vì sao Anthropic SDK có thể trao cho công cụ một JSON schema được suy ra từ model của bạn. Hint không bao giờ bị ép buộc bởi chính trình thông dịch — x: int = "hello" chạy bình thường — nên thỏa thuận là: bạn chú thích, pyright kiểm tra tĩnh, pydantic ép buộc ở các ranh giới.

dataclasses so với pydantic v2: biết bạn đang ở ranh giới nào

Cả hai đều cho bạn các lớp bản ghi có gõ kiểu. Khác biệt là độ tin cậy: dataclass giả định dữ liệu đã đúng (không xác thực, thuộc stdlib, cực nhanh); pydantic giả định dữ liệu là thù địch cho đến khi được chứng minh ngược lại (xác thực ở thời điểm chạy, ép kiểu, xuất JSON Schema). FastAPI: Express, nếu Express xác thực mọi thứ miễn phí

FastAPI là framework web mặc định cho các dịch vụ AI, và nó sẽ khiến bạn cảm thấy như về nhà: decorator cho route, handler async, middleware. Điều tốt hơn Express: thân request và response là các model pydantic, nên xác thực, tuần tự hóa, và tài liệu API tương tác (/docs, OpenAPI tự sinh) đều rơi ra từ annotation kiểu. Ba khái niệm đáng học đúng cách:

  • Endpoint có gõ kiểu. Khai báo model request làm tham số và model response trong decorator; FastAPI từ chối dữ liệu vào sai bằng mã 422 có cấu trúc trước khi mã của bạn chạy.
  • Tiêm phụ thuộc (dependency injection) với Depends. Các tài nguyên dùng chung (client Anthropic, cài đặt, xác thực) được khai báo làm tham số hàm — có thể kiểm thử bằng cách ghi đè phụ thuộc, không cần framework giả lập.
  • Endpoint async + streaming. Handler async def cho phép một worker giữ hàng trăm cuộc gọi LLM đồng thời (chúng là các khoản chờ IO-bound); StreamingResponse chuyển tiếp luồng token của Claude tới trình duyệt dưới dạng server-sent events.
from fastapi import FastAPI, Depends
from anthropic import AsyncAnthropic

app = FastAPI(title="summarizer")
def get_client() -> AsyncAnthropic: return AsyncAnthropic()

class SummarizeIn(BaseModel):  text: str = Field(min_length=1, max_length=50_000)
class SummarizeOut(BaseModel): summary: str; input_tokens: int

@app.post("/summarize", response_model=SummarizeOut)
async def summarize(body: SummarizeIn, client: AsyncAnthropic = Depends(get_client)):
    msg = await client.messages.create(
        model="claude-haiku-4-5-20251001", max_tokens=300,
        messages=[{"role": "user", "content": f"Summarize in 3 sentences:\n\n{body.text}"}])
    return SummarizeOut(summary=msg.content[0].text, input_tokens=msg.usage.input_tokens)
Sự tự phá hoại kinh điển của FastAPI: khai báo async def rồi gọi một thư viện chặn bên trong (sync requests, pandas nặng, time.sleep). Một request chậm đóng băng mọi request trên worker đó. Quy tắc: bên trong async def, mọi lời gọi IO phải được await (dùng httpx.AsyncClient, AsyncAnthropic); nếu buộc phải chặn, hãy làm endpoint là def thường và FastAPI sẽ chạy nó trong một thread pool cho bạn.

Xử lý đồng thời: khác biệt giữa 4 phút và 20 giây

Đây là khối lượng công việc định nghĩa Python FDE: chạy N prompt với một mô hình. Một bản đánh giá trên 200 trường hợp kiểm thử, một backfill trên 10.000 tài liệu, một dịch vụ phân loại dưới tải — tất cả cùng một hình dạng. Mỗi cuộc gọi là ~2 giây chờ đợi trên mạng. Tuần tự: 200 × 2s ≈ 7 phút; với 10.000 tài liệu, 5 tiếng rưỡi — buổi chiều của bạn biến mất và buổi demo khách hàng trượt. Đồng thời với 10 cuộc gọi đang bay: cùng 200 cuộc gọi hoàn thành trong ~40 giây. Không gì trong module này mang lại lợi ích nhanh hơn phần này.

Mẫu chuẩn: gather + semaphore

Xử lý đồng thời không giới hạn là một vụ từ chối dịch vụ tự gây ra — bắn 500 cuộc gọi đồng thời và bộ giới hạn tốc độ của nhà cung cấp sẽ nghiền nát bạn bằng các mã 429. Mẫu sản xuất luôn là xử lý đồng thời có giới hạn: asyncio.gather để chạy mọi thứ, asyncio.Semaphore để giới hạn số cuộc gọi thực sự đang bay. Ghi nhớ hình dạng này; Bài thực hành 3 bắt bạn đo lường nó: 

import asyncio
from anthropic import AsyncAnthropic

client = AsyncAnthropic()
sem = asyncio.Semaphore(10)                 # at most 10 requests in flight

async def classify(text: str) -> str:
    async with sem:                        # waits here if 10 are already running
        msg = await client.messages.create(
            model="claude-haiku-4-5-20251001", max_tokens=10,
            messages=[{"role": "user", "content": f"Category, one word: {text}"}])
        return msg.content[0].text

async def main(texts: list[str]) -> list[str | Exception]:
    return await asyncio.gather(*(classify(t) for t in texts),
                                return_exceptions=True)  # one failure ≠ lose the batch

GIL: nó thực sự có nghĩa gì với bạn

Global Interpreter Lock của Python chỉ cho phép một luồng thực thi bytecode Python tại một thời điểm. Sắc thái quan trọng: GIL được nhả ra trong lúc chờ IO — gọi mạng, đọc đĩa. Nên với công việc IO-bound (chiếm 95% công việc ứng dụng AI: bạn luôn chờ một mô hình), async cho bạn toàn bộ sự đồng thời cần thiết trên một luồng duy nhất, giống hệt Node. Nơi GIL cắn là Python CPU-bound: tạo 8 luồng để băm số cho bạn tốc độ bằng không vì chúng thay phiên nhau giữ khóa. Bảng quyết định:

Khối lượng công việcVí dụNên dùng
IO-bound, có thư viện asyncGọi LLM, truy vấn DB, HTTP fan-outasyncio + semaphore — mặc định của bạn, bao phủ gần như mọi thứ
IO-bound, thư viện chỉ có syncSDK cũ, một số trình điều khiển DBLuồng (asyncio.to_thread) — ổn, GIL được nhả ra trong lúc chờ
CPU-bound, Python thuần túyPhân tích/cắt khối một triệu tài liệumultiprocessing / ProcessPoolExecutor — các tiến trình riêng, các GIL riêng
CPU-bound, số họcToán embedding, thao tác dataframenumpy/pandas — phần nặng nằm trong C, GIL hầu như không tham gia
Kinh nghiệm thực địa: nếu bạn bị cám dỗ bởi multiprocessing, trước tiên hãy kiểm tra xem một thư viện đã giải quyết nó bằng C chưa (numpy, pandas, tokenizers). Qua nhiều năm làm dịch vụ AI, bạn sẽ dùng asyncio hằng tuần, luồng hằng tháng, và multiprocessing khoảng hai lần — thường cho việc tiền xử lý kho ngữ liệu một lần.

async def one(sem: asyncio.Semaphore, i: int, prompt: str) -> dict:
    async with sem:
        t0 = time.perf_counter()
        msg = await aclient.messages.create(model=MODEL, max_tokens=100,
            messages=[{"role": "user", "content": prompt}])
        return {"i": i, "latency": round(time.perf_counter() - t0, 2),
                "out": msg.content[0].text,
                "tokens": msg.usage.output_tokens}

async def run_concurrent(limit: int) -> float:
    sem = asyncio.Semaphore(limit)
    t0 = time.perf_counter()
    results = await asyncio.gather(
        *(one(sem, i, p) for i, p in enumerate(PROMPTS)),
        return_exceptions=True)
    elapsed = time.perf_counter() - t0
    ok = [r for r in results if not isinstance(r, Exception)]
    with open(f"batch_{limit}.jsonl", "w") as f:
        for r in ok: f.write(json.dumps(r) + "\n")
    print(f"limit={limit}: {len(ok)}/50 ok in {elapsed:.1f}s")
    return elapsed

if __name__ == "__main__":

    for limit in [5, 10, 25]:
        asyncio.run(run_concurrent(limit))

async def with_retry(coro_fn, retries: int = 4):
    for attempt in range(retries):
        try:
            return await coro_fn()
        except anthropic.RateLimitError:
            wait = 2 ** attempt        # 1, 2, 4, 8s — exponential backoff
            await asyncio.sleep(wait)
    raise RuntimeError("rate-limited after retries")

src/app/main.py — ba route, một trong số đó streaming SSE: 
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from . import llm
from .schemas import SummarizeIn, SummarizeOut, ExtractIn, Entities

app = FastAPI(title="ai-doc-service", version="0.1.0")

@app.post("/summarize", response_model=SummarizeOut)
async def summarize(body: SummarizeIn) -> SummarizeOut:
    text, tin, tout = await llm.summarize(body.text, body.style)
    return SummarizeOut(summary=text, input_tokens=tin, output_tokens=tout)

@app.post("/extract", response_model=Entities)
async def extract(body: ExtractIn) -> Entities:
    return await llm.extract_entities(body.text)

@app.post("/summarize/stream")
async def summarize_stream(body: SummarizeIn) -> StreamingResponse:
    async def sse():
        async for chunk in llm.stream_summary(body.text):
            yield f"data: {chunk!r}\n\n"
        yield "data: [DONE]\n\n"
    return StreamingResponse(sse(), media_type="text/event-stream")
