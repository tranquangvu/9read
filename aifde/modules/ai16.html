Red-teaming & Adversarial Evaluation

Attacking your own system on purpose, on a schedule, with evidence. The attack taxonomy, generating a corpus the way you generate tests, automating it in CI, the tool surface that agents expose, and the report a security team signs.

Why it matters for an FDE: the last gate before production is almost never technical — it is a security review. "We tested it and it's safe" fails that meeting. A tagged attack corpus, a pass/fail matrix by severity, each failure mapped to a control, and a CI gate that blocks regressions turns a six-week security discussion into a one-hour one. This is the module that converts a pilot into a deployment.

0
No exposure. Assumes the provider's safety training is the application's security posture.
1
Awareness. Can name prompt injection; has tried a few jailbreaks by hand and kept no record.

Independent production (target). Maintains a tagged attack corpus, scores it automatically in CI, maps every failure to a control, and reports by severity.

Leads & coaches. Runs the red-team program for an account — cadence, disclosure, severity policy — and trains delivery teams to attack their own work.

In the field

A bank's security team blocks a support-assistant launch with one sentence: "demonstrate it can't be made to leak another customer's data". The delivery team has been iterating on features for nine weeks and has no evidence of any kind.

The score-2 move is a document explaining the guardrails. The score-3 FDE spends an hour attacking the assistant by hand, turns those attempts into a 240-case corpus across six families, and runs it: 31 succeed, all in two families — cross-tenant retrieval and tool-argument injection. Two controls from PR4 later the corpus runs clean, and the gate is in CI so it stays that way.

The security team signed off on the matrix, not the assistant. What they were buying was the promise that the next release gets attacked too, automatically, before they ever see it.

Resources

  • Anthropic — Mitigate jailbreaks and prompt injections — the vendor's own mitigation guidance; the control side of every finding you file.
  • Anthropic — Develop tests — the harness shape the red-team corpus reuses instead of reinventing.
  • Anthropic — Tool use — the agent attack surface: schemas, arguments and results are all attacker-reachable.
  • Anthropic Engineering — Writing tools for agents — tool contracts that are hard to misuse, which is most of the agentic fix.
  • OWASP — Top 10 for LLM applications — the shared vocabulary a customer's security team will already be using in the review.
  • OWASP — Prompt injection prevention cheat sheet — concrete controls, mapped to the injection families in Part II.
  • NIST — AI Risk Management Framework — the risk language enterprise governance functions expect in the report.
  • Microsoft Learn — Planning red teaming for LLMs — a workable program cadence: who attacks, how often, and what gets recorded.
