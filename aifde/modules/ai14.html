Text-to-SQL & Structured Data

The other half of enterprise knowledge lives in the warehouse. Schema linking, the generate–validate–repair loop, read-only governance a DBA will sign, execution accuracy as the only honest metric, and the router that decides SQL versus retrieval per question.

Why it matters for an FDE: "can it answer questions about our data?" is the second thing every customer asks after document search, and it is the one where a wrong answer looks most authoritative. A number with a currency symbol in front of it gets pasted into a board deck. The FDE who ships text-to-SQL with an execution-accuracy number and a read-only sandbox is trusted with the warehouse; the one who demos a clever query and moves on is not.

LAB 1 ~2 h

Minimal NL→SQL, no framework

A real schema in DuckDB, a prompt, and a query you actually execute — so you own every step before a library hides it.

LAB 2 ~2.5 h

Schema linking & the repair loop

Retrieve the right tables, few-shot the hard joins, and feed the database's own error back to the model until it compiles.

LAB 3 ~2 h

The read-only sandbox

Least-privilege role, statement timeouts, row caps, row-level security — then try to exfiltrate data and fail.

LAB 4 · EVIDENCE ~3 h

The execution-accuracy report

A 25-question golden set scored by result equivalence, plus a working router that sends policy questions to RAG.

In the field

A retail customer wants "ChatGPT for our sales data". The pilot answers instantly and confidently; a regional manager notices the Q3 figure is 11% off because the model joined on store_id where it should have used location_key.

The score-2 move is to add "be careful with joins" to the prompt. The score-3 FDE builds a 25-question golden set with hand-verified result sets, measures execution accuracy at 52%, and finds every failure in one place: the model never saw the foreign-key relationships. Schema linking with FK metadata and six few-shot joins takes it to 91%, and the remaining failures now refuse instead of guessing.

The number that mattered to the customer was not 91%. It was that the other 9% say "I can't answer that" instead of inventing a figure someone would have presented to a board.

Resources

  • Anthropic — Tool use — the execution surface for a query tool, including how to return database errors the model can act on.
  • Anthropic — Structured outputs — schema-true generation, so the query and its parameters arrive as data rather than prose.
  • DuckDB documentation — the zero-setup warehouse used in Labs 1 and 4; its error messages are unusually good for repair loops.
  • PostgreSQL — Row-level security — the mechanism that makes per-user data access a database guarantee rather than a prompt request.
  • PostgreSQL — statement_timeout — the single setting that stops a generated query from taking the warehouse down.
  • Snowflake — Access control — role and grant model for the most common enterprise warehouse.
  • Google Cloud — BigQuery access control — the equivalent when the customer is on GCP.
  • Databricks — Unity Catalog — governed metadata and lineage; the semantic-layer story on the lakehouse side.
