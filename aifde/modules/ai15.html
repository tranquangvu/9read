Multi-agent Systems

Two or more agents with separate context windows: when that genuinely helps, the four topologies worth knowing, handoffs as typed contracts, shared state without corruption, and the spend ceiling that stops enthusiasm becoming an invoice.

Why it matters for an FDE: customers ask for "a team of AI agents" because it sounds like org structure they recognise. Most of the time the honest answer is one agent with better tools, and saying so saves a quarter of wasted delivery. The FDE who can show a bake-off — multi-agent versus single-agent, same task, measured cost, latency and quality — earns the right to be believed on the rare occasion the answer is yes.

In the field

A customer's innovation team has built a five-agent "research department" — planner, two researchers, critic, writer. It produces good reports in six minutes at about $1.80 each, and it fails opaquely about a fifth of the time.

The score-2 move is to add a sixth agent to supervise the other five. The score-3 FDE runs the same twenty reports through a single agent with a search tool and a longer context: quality scores within noise on the eval, 90 seconds, $0.31. The multi-agent version wins on exactly one report class — competitive teardowns needing genuinely parallel deep reads — so that route keeps two workers and the rest collapses to one agent.

Recommending the deletion of four fifths of someone's architecture is not a comfortable meeting. Bringing the trace, the cost table and the one case where their design was right is what makes it a short one.

Resources

  • Anthropic Engineering — Building effective agents — the argument for the simplest structure that works; read it before designing any swarm.
  • Anthropic Engineering — Multi-agent research system — a production multi-agent system described honestly, including where the cost went.
  • Anthropic — Tool use — the handoff mechanism; a worker interface is a tool schema.
  • Anthropic — Structured outputs — how to make a handoff payload schema-true instead of hoping it parses.
  • Anthropic — Claude Agent SDK — subagents, permissions and session state without hand-rolling the loop.
  • LangGraph — Multi-agent concepts — supervisor and swarm topologies expressed as a graph, with the handoff primitives named.
  • Temporal — Understanding Temporal — durable execution, for when workers must survive a process restart mid-run.
  • OpenTelemetry — Traces — spans and parent-child relationships; the shape a replayable multi-agent trace needs.
