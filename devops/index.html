DevOps Engineer
AWS Career Track · L0 → Senior

From "what is a server?" to
senior DevOps engineer on AWS

DevOps is the job of getting software to production quickly and keeping it there safely. This track takes someone who has never run infrastructure through Linux and networking, core AWS, Terraform and GitHub Actions, containers on ECS and a deep Kubernetes/EKS track, then observability, SRE, security and the architecture and leadership work that makes someone senior. It covers 52 modules in 10 tracks across 4 career levels, all on the stack Golden Owl runs for clients.

52 modules 10 tracks L0 → L3 13 Kubernetes / EKS modules Scored 0 → 4, target = 3

One stack, learned end to end

Every module uses the same tools and the same running example: the clinic booking platform (booking-api, booking-web, booking-worker, RDS Postgres, Redis, S3, SQS) in ap-southeast-1. Follow a change from a commit to a pod serving traffic.

How to use this program

1
Find your level

Score yourself on the modules of the level below yours. If every Core module is a 3, start at the next level.

2
Build it for real

Work in a sandbox AWS account with a budget alarm. Every module builds part of the clinic platform, and you can use Claude Code to write the code.

3
Tick the evidence

Each module ends with an evidence checklist. The last item is always a practice task that produces something you can show.

4
Pass the capstone

Each level ends with a capstone that a senior engineer reviews. Passing it, plus the rubric below, is what gets you promoted to the next level.

Scoring scale: 0 no exposure · 1 awareness · 2 works with support · 3 works independently (target) · 4 leads & coaches. Everyone takes the Core modules of their level. Take an Elective module when your project needs it, or as preparation for the next level.
Sandbox rule: practise only in your own sandbox account from the training OU. It must have a monthly budget alarm (USD 50 is a sensible default), and you run terraform destroy at the end of each session. NAT gateways, EKS control planes and idle load balancers bill by the hour whether you use them or not.

Level capstones

Each capstone builds on the previous one. By L3 you have built the whole clinic platform yourself.

L0 · Ship it on one box
  • booking-api in a multi-stage, non-root image under 150 MB, with a compose file that runs API, Postgres and Redis
  • Running on a Linux VM as a systemd service behind nginx with TLS
  • A troubleshooting write-up for one failure the reviewer injects (full disk, port clash or bad DNS)
L1 · A real AWS environment
  • Terraform for a 3-AZ VPC, ALB, an EC2 Auto Scaling group or Lambda, RDS, S3 + CloudFront, Route 53 + ACM
  • GitHub Actions with OIDC: plan on PR, apply on merge, app build and deploy
  • No IAM users, no public data stores, and a one-page diagram plus a cost estimate
L2 · Own production on EKS
  • EKS cluster via Terraform with Karpenter, the AWS Load Balancer Controller, Pod Identity and External Secrets
  • The three services as Helm charts, deployed by Argo CD with an Argo Rollouts canary
  • OpenTelemetry → Prometheus/Grafana and Datadog, two SLOs with burn-rate alerts, and a runbook used in a mock incident
L3 · Design the platform
  • A design doc for a multi-account landing zone with central networking, logging and security services
  • A DR plan with RTO/RPO targets, proven by a game day with AWS FIS
  • A FinOps report that cuts the platform's bill by a measured amount, and a mentoring record for one L1 engineer
